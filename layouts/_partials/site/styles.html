Order is the cascade: tokens and faces first, then the shared core, then the chrome, then the bricks. `sections/*.css` comes last so a brick can override the core, and no brick file depends on the order of another. In production the bundle is minified and fingerprinted, which is the cache busting; in development the filename is stable, so a query string does it. @context {page} . */ -}} {{- /* TEMPORARY: flip to false to ship the core and the chrome without any `sections/*.css`, to see what the bricks look like on the base styles alone.
